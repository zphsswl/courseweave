# 需求分析文档

> 项目名称：MedEssence Agent · 七书归一
>
> 版本：v1.0 | 最后更新：2026-05-10

---

## 1. 项目背景

医学教育中，学生需同时研读多部教材（如局部解剖学、生理学、病理学等），每部教材侧重点不同，知识点交叉关联但表述方式各异。传统学习方式面临三大痛点：

1. **信息碎片化**：同一知识点在不同教材中分散出现，学生难以建立全局认知
2. **检索效率低**：2567 页教材中定位特定知识点耗时巨大
3. **知识更新滞后**：教材内容往往落后于临床实践，缺乏专家修正机制

MedEssence Agent 旨在通过多 Agent 协作架构，实现 7 部医学教材的知识融合与智能问答，为医学生和教师提供高效的教辅工具。

## 4. 功能需求

### 4.1 P0 — 核心必备功能（MVP）

| 编号 | 功能 | 描述 | 涉及模块 |
|------|------|------|----------|
| F-01 | **教材PDF解析** | 支持 7 部教材 PDF 的上传、解析与文本提取 | Ingestion Agent |
| F-02 | **知识图谱提取** | 从教材文本中自动抽取实体（概念、疾病、解剖结构等）及其关系 | KG Extraction Agent |
| F-03 | **跨教材知识对齐** | 识别不同教材中描述同一实体的知识点，合并消歧 | Alignment Agent |
| F-04 | **知识智能压缩** | 在保留核心知识的前提下压缩至原始体积 30% | Compression Agent |
| F-05 | **RAG 问答** | 基于检索增强生成的自然语言问答，支持精确引用教材原文（章节+页码） | RAG Agent |
| F-06 | **教师反馈循环** | 教师对答案进行评价和修正，系统记录并纳入后续回答 | Teacher Dialogue Agent |
| F-07 | **知识图谱可视化** | 展示知识图谱的交互式可视化，支持缩放、搜索、高亮 | 前端 KG 页面 |
| F-08 | **多轮对话** | 支持对同一话题的追问与上下文保持 | RAG Agent + 前端 |

### 4.2 P1 — 重要功能

| 编号 | 功能 | 描述 | 涉及模块 |
|------|------|------|----------|
| F-09 | **学习报告生成** | 按学科/章节/知识点维度生成学习报告 | Report Agent |
| F-10 | **问答历史记录** | 保存用户问答记录，支持回溯与检索 | RAG Agent + SQLite |
| F-11 | **语义搜索** | 支持自然语言语义搜索，不限于关键词匹配 | RAG Agent |
| F-12 | **知识点交叉对比** | 对比同一知识点在不同教材中的表述差异 | Alignment Agent |
| F-13 | **精准引用展示** | 回答中展示引用原文片段、教材名、章节、页码 | RAG Agent |
| F-14 | **实体详情面板** | 点击知识图谱节点展示实体详情 | 前端 KG 页面 |

### 4.3 P2 — 增强功能

## 5. 非功能需求

### 5.1 性能

| 指标 | 目标值 | 测量方法 |
|------|--------|----------|
| 问答响应时间 | < 5 秒（平均） | 端到端计时（不含 LLM 流式输出） |
| 知识图谱加载时间 | < 3 秒（首次加载）< 1 秒（缓存后） | 页面加载计时 |
| PDF 解析速度 | < 30 秒/百页 | 单次解析任务计时 |
| 并发支持 | > 50 同时在线用户 | 压力测试 |
| 检索召回率 | > 85%（Top-5） | 标注测试集评估 |

### 5.2 可用性

| 指标 | 目标值 |
|------|--------|
| 系统可用性 | > 99%（服务时间） |
| 平均无故障时间 | > 72 小时 |
| 数据备份频率 | 每日自动备份 |

### 5.3 可扩展性

| 要求 | 描述 |
|------|------|
| 教材扩展 | 支持新增教材的解析与对齐，无需修改核心代码 |
| Agent 扩展 | 支持新增 Agent 类型，通过注册机制加入工作流 |
| 模型替换 | LLM 和后端模型可替换（本地 / API），配置驱动 |

### 5.4 安全性

| 要求 | 描述 |
|------|------|
| 数据隔离 | 不同用户数据物理隔离（多实例场景） |
| 输入校验 | 所有用户输入进行长度、格式校验，防止注入攻击 |
| API 鉴权 | 基础 Token 鉴权（教学场景，简化但不可少） |
| 敏感信息过滤 | 自动过滤问答中可能出现的个人信息 |

### 5.5 可用性

| 要求 | 描述 |
|------|------|
| 提示引导 | 问答框提供示例问题引导 |
| 错误提示 | 友好的错误提示与恢复建议 |
| 操作可逆 | 教师反馈支持回滚操作 |
| 响应式设计 | 支持 1024px+ 分辨率，优化桌面体验 |

## 7. 约束与假设

### 7.1 约束

| 类型 | 约束 | 说明 |
|------|------|------|
| **时间** | 5 小时 hackathon | 需优先完成 P0 功能 |
| **团队** | 有限开发人员 | 采用模块化分工 |
| **数据** | 教材版权受限 | 仅用于教育演示，不公开发布教材内容 |
| **计算资源** | 本地开发环境 | 需本地可运行的轻量方案 |
| **模型** | 本地 / API 混合 | 支持离线运行的小模型与云端大模型切换 |

### 7.2 假设

| 编号 | 假设内容 | 风险 |
|------|----------|------|
| A-01 | PDF 教材为可解析的数字 PDF（非扫描图片） | 若为扫描件需增加 OCR 流程 |
| A-02 | 教材结构相对规范（有章节标题、目录） | 若格式混乱需增加结构推断逻辑 |
| A-03 | 医学名词主要使用中文术语 | 中英文混合需额外处理 |
| A-04 | 用户网络环境可访问嵌入模型 | 需准备本地 fallback 方案 |
| A-05 | 教师用户具有领域专业知识 | 反馈质量依赖于教师专业水平 |

### 7.3 风险与缓解

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|----------|
| PDF 解析质量差 | 高 | 中 | 多引擎轮换 + 人工校验接口 |
| LLM 输出幻觉 | 高 | 中 | RAG 强制引用 + 教师反馈纠正 |
| 对齐效果不佳 | 高 | 低 | 多策略（语义+规则+人工）组合 |
| 性能瓶颈 | 中 | 中 | 缓存 + 异步处理 + 量化模型 |
| 5 小时时间不足 | 高 | 高 | P0 优先，P1/P2 后续迭代 |

## 8. 术语表

| 术语 | 英文 | 定义 |
|------|------|------|
| Agent | Agent | 具有特定功能的自主处理单元 |
| 知识图谱 | Knowledge Graph | 由实体和关系组成的结构化知识网络 |
| 知识对齐 | Knowledge Alignment | 识别并融合不同来源中的相同/相关知识点 |
| 知识压缩 | Knowledge Compression | 在保留核心信息的前提下缩减文本体积 |

| 编排 | Orchestration | 多个 Agent 的调度与协作管理 |
