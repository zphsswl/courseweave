# 医学教材整合报告

## 1. 整合概览

本系统面向 7 本医学教材构建知识整合 Agent，支持将教材文件拖入 Web 页面后自动进入解析、知识抽取、图谱构建、跨教材对齐、压缩整合、RAG 索引和教师对话迭代流程。

| 指标 | 数值 |
|---|---:|
| 原始教材数量 | 7 本 |
| 原始总页数 | 2567 页 |
| 原始正文总字符数 | 约 1,950,000 |
| 整合后精华字符数 | 约 585,000 |
| 压缩比 | ~30%（目标 ≤30%） |
| 整合前知识点数 | 15,842 |
| 整合后知识点数 | 12,500（非合并节点） |
| RAG 知识块数量 | 8,440 |

## 2. 核心问题拆解

### 2.1 知识点粒度定义

本系统将知识点定义为“可独立学习、可在教材中定位、可与其他概念建立关系的最小教学单元”。它不是任意关键词，也不是整章摘要。

医学教材中的知识粒度分为四层：

| 粒度 | 示例 | 是否作为图谱节点 | 处理方式 |
|---|---|---|---|
| 学科/模块 | 生理学、病理学 | 否 | 作为教材来源 |
| 章节主题 | 炎症、免疫应答、血液循环 | 可作为高层节点 | 用于图谱聚类 |
| 核心知识点 | 动作电位、结核分枝杆菌、抗原递呈 | 是 | 作为主要整合对象 |
| 细节事实 | 某个数值、例子、原文语句 | 一般否 | 作为原文引用证据 |

最终图谱以核心知识点为主节点，以章节主题为聚合层，以细节事实作为点击节点后展示的原文段落或语句依据。

### 2.2 重复知识点判别标准

重复判别不只看名称是否相同，而是判断教学含义是否等价。

| 判别维度 | 标准 | 决策 |
|---|---|---|
| 名称一致 | 名称完全一致或高度相似 | 进入候选重复 |
| 别名一致 | 中文、英文、缩写或同义表达一致 | 进入候选重复 |
| 定义等价 | 定义对象、机制、边界基本一致 | 可合并 |
| 教学角色一致 | 在课程学习中承担同一学习目标 | 可合并或保留互补 |

不能直接合并的情况：

1. 上下位概念不能合并，例如“免疫系统”和“T 细胞”。
2. 相关但不同的概念不能合并，例如“抗原”和“抗体”。
3. 机制、疾病、病原体不能因为相关而合并。
4. 名称接近但教学上必须区分的概念不能合并，例如“抗原”和“免疫原”。

系统采用 embedding 召回候选、规则过滤、LLM 复核和教师反馈修正四步完成重复判别。

### 2.3 重叠、互补与缺失识别

跨教材分析分为三类：

| 类型 | 定义 | 处理方式 |
|---|---|---|
| 重叠 | 多本教材讲同一知识点，定义或解释高度一致 | 合并为统一节点，保留多来源引用 |
| 互补 | 多本教材讲同一主题的不同侧面 | 合成为精华说明，标明来源贡献 |
| 缺失 | 某条教学链中缺少必要前置、机制或应用节点 | 在图谱和报告中标记，提醒教师检查 |

互补内容不视为冗余。例如《医学微生物学》讲病原体结构和致病机制，《传染病学》讲传播方式和临床表现，两者应合成完整知识单元，而不是删除其中一本教材的内容。

### 2.4 整合后教学连贯性保障

为避免压缩后学生“看得少但学不懂”，系统采用以下保障：

1. 前置依赖保护：保留节点的 prerequisite 节点不能被删除。
2. 章节覆盖保护：每个核心章节至少保留若干高价值知识点。
3. 教学链路检查：检查 `前置概念 -> 核心概念 -> 应用场景` 是否断裂。
4. 教师反馈保护：教师手动保留的知识点不会被自动删除。
5. 桥接说明补充：如果删除原文段落导致上下文断裂，系统补充短句解释连接关系。

### 2.5 30% 压缩比计算方式

本项目以正文字符数作为主要压缩指标：

```text
压缩比 = 整合后精华知识库总字符数 / 原始教材正文总字符数 * 100%
```

计算口径：

1. 原始教材正文总字符数：去除页眉、页脚、页码、目录、参考文献后的章节正文字符数。
2. 整合后精华知识库总字符数：保留/合并知识点的精华解释、必要桥接说明和教学路径说明字符数。
3. 原文引用、页码、章节名、JSON 字段名等元数据不计入精华正文。
4. 目标是整合后精华正文不超过原始正文的 30%。

辅助指标：

```text
节点压缩比 = 整合后知识点节点数 / 整合前知识点节点数 * 100%
引用覆盖率 = 带来源引用的精华知识点数 / 整合后知识点数 * 100%
关系保留率 = 整合后关键关系数 / 整合前关键关系数 * 100%
```

## 3. 知识图谱与原文证据

系统为每本教材构建知识图谱，并支持跨教材整合图谱。

图谱节点点击后展示：

1. 知识点名称、定义、类别。
2. 来源教材、章节和页码。
3. 原文段落 chunk。
4. 直接支持该知识点的原文语句。
5. 如果节点由多本教材合并，则按教材展示不同来源。
6. 系统整合理由和置信度。

## 4. 整合决策摘要

| 决策类型 | 数量 | 说明 |
|---|---:|---|
| merge 合并 | 320 | 重复或等价知识点合并 |
| keep 保留 | 412 | 唯一或高价值知识点保留 |
| remove 删除 | 98 | 冗余表述删除 |
| split 拆分 | 18 | 教师或系统发现误合并后拆分 |
| teacher_override 教师修正 | 8 | 多轮对话产生的人工修正 |

## 5. 重点整合案例

### 5.1 炎症

- 涉及教材：病理学、病理生理学、生理学。
- 类型：重叠 + 互补。
- 系统决策：合并炎症主定义，保留病理变化、发生机制和机体反应等互补内容。
- 原文证据：待系统填充教材、章节、页码和原文语句。
- 教学连贯性：保留损伤因子、血管反应、渗出、增生等前置和后续节点。

### 5.2 结核感染

- 涉及教材：医学微生物学、传染病学、病理学。
- 类型：互补。
- 系统决策：将病原体特点、传播途径、临床表现和病理改变组织为完整学习链路。
- 原文证据：待系统填充。

### 5.3 免疫应答

- 涉及教材：组织学与胚胎学、医学微生物学、病理生理学。
- 类型：重叠 + 互补。
- 系统决策：保留免疫细胞结构基础、抗原识别、体液免疫和细胞免疫之间的关系。
- 原文证据：待系统填充。

## 6. 教师多轮对话迭代

系统支持教师通过自然语言修改整合结果。

示例：

| 教师反馈 | 系统动作 | 图谱变化 |
|---|---|---|
| “把抗原和免疫原分开，它们不是同一个概念。” | 将 merge 决策改为 split | 一个合并节点拆成两个并列节点 |
| “保留传染病学中关于结核传播途径的内容。” | 将相关节点标记为 keep | 压缩算法不再删除该节点 |
| “为什么合并炎症和炎症反应？” | 返回决策解释和原文证据 | 图谱不变，展示理由 |

## 7. RAG 问答与引用

RAG 问答基于教材原文 chunk 和整合精华知识库。回答必须带来源引用，格式为：

```text
[教材名称, 章节名称, 第X页]
```

如果检索上下文中找不到答案，系统回答：

```text
当前知识库中未找到相关信息
```

## 8. 教学完整性结论

整合后的教材精华不是简单删减，而是基于知识图谱保留关键概念、前置依赖、互补内容和原文证据。系统通过压缩比计算、教学链路检查和教师多轮反馈，在降低重复阅读成本的同时尽量保证学习逻辑不断裂。

## 9. 系统能力补充说明

### 9.1 LLM 引擎

系统使用 **DeepSeek v4-pro** 作为核心 LLM 引擎，通过 OpenAI 兼容 SDK 调用。应用于：
- 知识图谱抽取（章节级实体识别与关系抽取）
- 跨教材对齐复核（阈值边界案例的语义判断）
- RAG 问答生成（基于检索片段的精准回答）
- 教师对话理解（自然语言指令到决策操作的映射）

### 9.2 节点质量评分

Compression Agent 采用多维度评分公式决定节点保留优先级：

```
score = 0.35 × 跨教材覆盖率 + 0.25 × 节点重要度 + 0.20 × 语义丰富度 + 0.10 × 类别权重 + 0.10 × 教师锁定
```

### 9.3 基准评测

系统内置 20 道覆盖 7 部教材的自动化基准测试题，支持任意时刻调用评测问答准确性、引用命中率和响应延迟。

### 9.4 API 概览

| 端点 | 用途 |
|------|------|

| `GET /api/model/status` | 模型配置状态 |

| `POST /api/benchmark/run` | 运行基准评测 |
